# Проверка мобильного перехода из поиска

Сценарий выполняет **один** поисковый запрос в Google с эмуляцией мобильного браузера, ищет обычный результат для `alcohub-msk.com`, переходит на него и нажимает до трёх ссылок категорий на странице. Не нажимает кнопки звонка, не отправляет формы и не совершает заказ. Запускается только с явным флагом `--live`.

Внимание: автоматические запросы к Google без разрешения нарушают его условия; искусственные клики могут игнорироваться и не гарантируют рост позиций. Работа скрипта может привести к ограничениям со стороны Google. При CAPTCHA или запросе согласия скрипт останавливается — решения или обхода в нём нет. Разметка Google может измениться; наличие сайта в поисковом индексе не гарантирует его нахождения по конкретному запросу на первой странице. Некоторые посетители могут не попасть на сайт из-за действующего ограничения на referrer.

## Установка на своём сервере

Нужны Node.js 20+ и зависимости браузеров Chromium и WebKit для Linux. Для профилей iPhone нужен WebKit, одного Chromium недостаточно. В этой папке:

```sh
npm ci
npx playwright install --with-deps chromium webkit
npm test
```

Проверка с реальным Google (нажмите один раз, задание из одного запроса):

```sh
npm start -- --live --query 'доставка алкоголя москва'
```

Чтобы выбрать профиль iPhone 13 для отдельного теста, после установки WebKit укажите `--scenario 3`:

```sh
npm start -- --live --scenario 3 --query 'доставка алкоголя москва'
```

Первый сценарий по умолчанию — Pixel 5. Номера 3–8 соответствуют iPhone 13, iPhone 15, iPhone 15 Pro, iPhone 17, iPhone 17 Pro и iPhone 17 Pro Max. Например, для iPhone 17 используйте `--scenario 6`. Без `--live` запросы не отправляются.

Для диагностики проверки Google можно добавить `--diagnose-challenge`: при обнаружении CAPTCHA сценарий выведет адрес без параметров, заголовок и до 1500 символов текста страницы, после чего остановится. Текст может содержать IP и другие данные; проверяйте перед публикацией. Этот режим не решает CAPTCHA, не гарантирует определения её типа и не продолжает сессию после проверки.

## Несколько сценариев

`queries.json` содержит поисковые фразы; изменяйте их как обычный JSON-массив строк. Пакет выполняет отдельные браузерные сессии **последовательно**, через случайную паузу от 30 до 90 секунд между ними. Каждая сессия вводит запрос с задержкой, выдерживает короткие паузы и выбирает от одного до трёх разных разделов в случайном порядке. Это не 100 отдельных физических телефонов, пользователей или IP-адресов. Для каждого номера сценария по очереди выбирается один из стандартных профилей Playwright: Pixel 5, Pixel 7, Galaxy S9+, iPhone 13, iPhone 15, iPhone 15 Pro, iPhone 17, iPhone 17 Pro или iPhone 17 Pro Max. Android-профили используют Chromium, iPhone — Playwright WebKit. Linux WebKit — не настоящий Safari или физический iPhone и не копирует его полностью. Используются касания, короткие задержки и прокрутка на сайте; язык — русский, часовой пояс — Москва. Это эмуляция браузера, не физические телефоны. Вариативность предназначена для разнообразия тестов, **не делает искусственный трафик настоящим и не гарантирует, что автоматизацию не обнаружат**. Профили запускаются без входа в Google, с новым чистым контекстом и одним серверным IP; прокси и обход CAPTCHA не предусмотрены.

```sh
npm run batch -- --count 100           # только распечатать план, без запросов
npm run batch -- --live --count 1      # один реальный тест
npm run batch -- --live --count 100    # до 100 последовательных сессий
```

При такой задержке 100 сессий займут не менее 49,5 минут и до 148,5 минут только на промежутки между сессиями, плюс время каждой проверки. Если сайт не найден на первой странице, этот запрос пропускается. При CAPTCHA, отказе Google, ошибке загрузки или блокировке сайта весь пакет останавливается; повторного запуска нет. Остановить программу можно с помощью Ctrl+C.

Без `--live` реальный поиск не выполняется. Скрипт не пытается обойти ограничения и не использует сторонние прокси. Формат поисковой страницы может измениться: проверяйте его перед реальным запуском; селекторы не гарантируют безошибочного распознавания рекламных блоков.

Результаты выводятся в консоль. Можно дополнительно сохранять журнал (JSONL, одна строка на завершённую сессию):

```sh
npm run batch -- --live --count 1 --report ./reports/sessions.jsonl
```

В журнале: время начала и конца, запрос, номер сценария, профиль устройства и результат (`visited` — сценарий завершился без ошибки, `not_found` — результат не найден на первой странице, `stopped` — ошибка или остановка), код и сигнал процесса. Подробная причина ошибки остаётся в консоли. Внезапное завершение процесса может оставить незаписанную текущую сессию; журнал не гарантирует полноту. Файл может содержать поисковые фразы — храните его приватно и не публикуйте. Журнал не доказывает, что Google засчитал клик или изменил позиции. Для оценки реальных запросов используйте Search Console; вызовы этого инструмента могут исказить статистику посетителей и не являются реальными заказами.
